综合任务优化（任务条件优化 + 击杀任务可用武器 + 任务链提示 + 任务名标记） v1.4.0 — 安装必看
============================================================================

纯服务端 mod，不需要装任何客户端插件。适用 SPT 4.1.6。


【安装前必读：先把这些旧件删掉】

★ 本包是「三合一」：把原先分开发布的三个东西并进了一个 DLL。
  装过下面任何一个的，【先删掉再装本包】，否则会冲突（症状写在每一条后面）：

   ① 任务链提示 v1.0.0          → user\mods\QuestChainHint41\
   ② 击杀任务可用新武器 v2.4.1   → user\mods\AddNewWeaponsToQuest41\
      不删的症状：任务描述里出现两条一模一样的「前置任务 / 后续任务 / 等级需求」前缀。
   ③ 旧内测客户端「可用武器」面板 → <游戏目录>\BepInEx\plugins\QuestTuner41Client\
      （顺手删 BepInEx\config\com.zcode.questtuner41.ui.cfg）
      不删的症状：已下线的面板还在，且会盖掉服务端的设置。

★ 怎么删：整个目录删掉，或整个移到 <SPT_Runtime>\user\mods_disabled\。
  ★目录名不要自己加「.停用」之类后缀，SPT 不认，等于没停用。

★ 删 ① 之前先备份它的 config.jsonc —— 你调过的链条参数（颜色 / 文案 / 开关 / 黑名单）在里面。
  本包启动时会读这份旧配置并整段覆盖新 config.json 的 ChainHint 分区，老调参不会丢；
  但旧目录一旦删掉，这份兼容读取就没了，分区会退回默认值。
  正确顺序：① 备份旧 config.jsonc；② 删或移走旧 mods 目录；
  ③ 把要保留的值抄进新 config.json 的 "ChainHint" 分区；④ 重启服务端。


【一分钟安装】
0) 先按上面的【安装前必读】把旧件删掉（装过的话）。
1) 备份：把 <SPT_Runtime>\user\mods\QuestTuner41\（如有）整个移到别处。
2) 把本包里的 SPT_Runtime\ 整个合并到服务端根目录（与 SPT.Server.exe 同级那层）。
3) 启动 <SPT_Runtime>\SPT.Server.exe，日志出现「服务端已开启，游戏愉快」后再开游戏。
4) 验证：打开 <SPT_Runtime>\user\logs\spt\spt<日期>.log，搜这两行：
      模组：综合任务优化 版本1.3.0 ... 作者：DSH 已加载
      [启动末段] 扫描 N 个任务 / 本遍改动 M 处
    且全文无 Critical。


★ 装过本 mod 早期版本的：第 2 步请照【升级】那一节做，【只换 DLL、不要覆盖 config.json】，
  否则你自己调过的参数会被包里的出厂默认值抹掉。


【功能特性】

1) 任务条件优化 —— 去掉任务里那些限制
   · 去掉「必须用指定武器 / 指定配件 / 限定距离 / 限时 / 限定地图 / 限定区域 /
     限定部位 / 装备要求 / 伤势要求 / 撤离前必须做完某事」
   · 「击杀 Scav」可改成「击杀任意目标」，PMC 条件同样可改
   · 去掉区域限制：任务仍然限定在原来那张地图，只是不再限定图内某个区域（不是去地图限制）
   · 击杀数 / 上交数可设固定值或百分比
   · 「不限 AI 种类」与失败条件自动配对：完成侧放宽成「任意目标」时，
     同任务里矛盾的「杀某类 AI 即失败」会一并移除（带指定角色的失败条件保留）
   · 支持排除清单、只看清单、逐任务覆盖、排除日常周常

2) 击杀任务可用武器 —— 让 mod 的新枪也能算数
   · 「必须用指定枪击杀」的任务，自动把你已装其他 mod 的新武器算进可用列表
   · 接取任务后商人会额外发一条「本任务可用武器」清单消息
   · 任务描述里补两段：橙色「本任务要求使用：…」写任务原本点名（或不点名）的那把枪，
     黄色「可用武器：…」写扩充后的完整名单（默认只列前 10 把）
     ★「本任务要求使用」是全量列出的（某些任务原版就要求几十把枪，会很长），
       名字末尾的六位方括号是物品 ID 后六位，同名不同色号的枪靠它区分；
       与物品染色类 mod 共存时颜色标签已剥除，不会互相覆盖。
   · v1.4.0 起按【原型】认枪：模组里照原版枪改出来的变体（DWV 的各种改型、SOCOM 的 DDM4A1、
     WTT 的 Ak5C 等）只要用的是同一把原版枪的模型容器，就和原版那把、以及同族的其它变体互相算数，
     双向生效。以前只认「声明了克隆关系」的武器，这类变体全被漏掉，任务死守「必须用那一把」。
   · 支持按物品 ID / 按来源 mod 整包排除，也支持手工加映射

3) 任务链提示 —— 把前置后续写进任务描述
   · 任务描述里标出：前置任务、后续任务、等级需求（红 / 浅蓝 / 绿三色分段）
   · 链条在条件改写完成之后才计算，不会出现「任务已放开、界面仍写着前置」的矛盾
   · 条数、展开层数、三段各自都能单独开关，嫌烦可整块关掉

4) 任务名优化标记 —— 一眼看出哪些任务被改过（v1.2.0 起，v1.3.0 拆成两类）
   · 被改过【条件】的任务，任务名后面挂「（任务已优化）」
   · 【武器池真的往这个任务的条件里加过枪】的任务，挂「（武器已优化）」
   · 两枚标记各算各的，同一个任务可以同时挂两枚
   · 默认全开，共 442 个任务带标记（约占全部任务名的 16%）
   · 嫌太吵就整个关掉：把两个后缀键都填成空字符串即可


【配置】
全部配置在 user\mods\QuestTuner41\config.json 一个文件里。
出厂文件每个键都带中英文注释；可以写 // 注释、可以留尾逗号，解析时都会跳过。
改完保存 → 重启服务端生效。

★ 出厂默认即可直接用：只开了「击杀 Scav 改成任意目标」，其余全关。
★ 别整份从别处覆盖 config.json —— 里面可能混着你自己的调参，按键改更安全。
★ 改 cfg 前不要按 F12：F12 会把内存里的旧值写回磁盘，覆盖你刚改的内容。

关于任务名标记（v1.2.0 / v1.3.0 新增的两个键）
  "questNameSuffix": "（任务已优化）"    ← 条件被改过的任务
  "weaponNameSuffix": "（武器已优化）"   ← 武器池真的给它加过枪的任务
  两个都填成 ""（空字符串）＝ 关掉；只关其中一族＝ 把那个键单独填成 ""。
  想换成自己的文字，直接写进引号里即可，比如 "★改"。

常见组合（直接照抄）
  去掉任务里所有限制：
    "removeTime": true, "removeDistance": true, "removeZone": true,
    "removeFindInRaid": true, "removeSelfHealthEffect": true
  PMC 也算任意目标 + 难度加倍：
    "replacePmcWithAny": true, "harderPmc": true, "harderPmcMultiplier": 2
  不想看到任务名上的标记：
    "questNameSuffix": "", "weaponNameSuffix": ""
  只留「武器池给它加过枪」的那类标记：
    "questNameSuffix": ""
  不想看到链条文本：
    "ChainHint": { "Enabled": false }
  链条太长，只看前 5 条：
    "ChainHint": { "MaxUnlockShown": 5, "MaxPrerequisiteShown": 5 }
  接任务时别再发武器清单：
    "weaponPool": { "sendWeaponListOnQuestAccept": false }
  某个 mod 的武器不想进池（填它的目录名）：
    "weaponPool": { "excludeMods": ["某个Mod目录名"] }
  只处理某几个任务 / 排除某几个任务：
    "onlyQuests": ["任务ID"], "exemptQuests": ["任务ID"]
  日常周常也一起改：
    "affectRepeatables": true
  先看看会改多少又不真的改：
    "dryRun": true   // 看日志汇总，确认后改回 false


【升级】

★ 从早期版本升到 v1.3.0：只换 DLL，别动你的 config.json
   正确做法：
     ① 把 user\mods\QuestTuner41\ 整个复制一份到别处（备份，回滚要用）；
     ② 只把包里的 QuestTuner41.dll 和 安装必看.txt 覆盖进去；
     ③ config.json 【保留你自己那份】，不要用包里的覆盖。
   为什么强调第 ③ 步：包里的 config.json 是出厂默认值，你之前改过的开关、豁免清单、
   链条黑名单全在里面，一覆盖就全没了。config.json 是唯一需要你手动处理的文件。

   覆盖完直接启动就行，配置不用改：
     · 早期版本里写着 "markerSuffix": " (S4A)" 的，那个任务目标行尾的暗号已经不用了，
       新版起服时会自动把它关掉，并在日志里报一行「配置已自动升级 N 项」说明改了什么。
     · 新增的两个标记键你那份 config.json 里没有，会自动取出厂默认值，不用手写。
     · ★只有「出厂默认值」会被自动改，你自己写过的任何值一律原样保留。
     · ★本 mod 不会回写你的 config.json（写了会把里面 60 多行中文注释全部抹掉），
       所以上面那行提示每次启动都会出现一次，属于正常。
   回滚：把第 ① 步备份的整个目录复制回去即可。

★ 旧组件（任务链提示 / 击杀任务可用新武器 / 旧客户端面板）的删除办法与顺序，
   见文件开头的【安装前必读：先把这些旧件删掉】——那一步要在装本包【之前】做完。


【日志与排查】
服务端日志：<SPT_Runtime>\user\logs\spt\spt<日期>.log（时间戳是 UTC，比本地慢 8 小时）
汇总行长这样，括号里每个数字对应 config.json 的一个开关，一眼看出谁在起作用：
  [启动末段] 扫描 2013 个任务 / 本遍改动 5416 处 / 累计 22381 处
  （目标 356、…、配对中和 3、移除区域 40、…；武器池 +22205；池缺失 717；
    任务名标记 311；武器名标记 234）

常见现象
  · 任务名后面没有标记 → 看汇总行末尾的「任务名标记 / 武器名标记」，两个都是 0 就是没挂上；
    对照 config.json 里两个后缀键有没有被写成空字符串
  · 描述里出现两条一模一样的链条前缀 → 旧 mods 目录还在，见【升级】
  · 任务链模块日志太吵 → config.json 里把 ChainHint.LogLevel 改成 quiet；
    要排查「某批任务没拿到链条」才改成 full
  · 某个任务的可用武器没出来 → 看汇总行的「池缺失 N」，
    多半是那把枪在物品表里不存在，用 autoScanMods 先扫一遍仍缺就手工加映射
  · removeZone 没生效 → 汇总行后的日志会逐条打「removeZone 未展开：任务 <id> …」，
    是该任务定位不到所属地图（任务级 location 写成 "any" 或自定义串），原样保留属正常
  · 日志里「任务名标记 311」而界面上只数到 307 个 → 差的 4 个是任务在汉化数据里
    没有对应名字，属正常


【兼容性】

· SPT 版本
  仅适用 SPT 4.1.6（声明 ~4.1.0），单机模式。纯服务端，不需要任何客户端插件，
  本包也不分发 BepInEx 目录。与 4.0 / 3.x / 4.2+ 不保证兼容。

· 日常 / 周常（Daily / Weekly）
  默认不改。config.json 里把 "affectRepeatables" 设为 true 才作用，范围与 sgtlaggyQuestTweaks
  的同名开关对齐：击杀目标、条件移除、数值面板三类会改；地图 / 区域 / 时间、装备 / 状态、
  隐藏目标、特殊任务处理这几类不动。

· 与 sgtlaggyQuestTweaks
  可以共存。本 mod 只动「击杀目标仍是 Scav / PMC」的条件，已经被对方改掉的条件不会被二次加工。
  它那边的 exemptQuests 本 mod 默认会一并读取并跳过（"honorSgtlaggyConfig": true），
  武器池也会按同一份名单跳过。
  ★两边都开了日常改写时，会出现重复改写，建议二选一。

· 与「改任务描述」类 mod（各类任务汉化件、任务增强件）
  可以共存，但有一个坑：用别的件重写任务 description 时，要剥掉本 mod 注入的链条文本，
  否则会出现两份「前置任务 / 后续任务 / 等级需求」。

· 与「改任务条件」类 mod
  同一个任务被两个 mod 同时改写时，以最后生效的那个为准。起服汇总行会报
  「其它改任务 mod N」，说明有别的 mod 也在改任务；数字看着不对时，先怀疑是它。

· 其它 mod 的武器（击杀任务可用武器）
  本 mod 起服时会扫描 user\mods 下所有 mod，把它们的克隆武器补进「击杀任务可用武器」名单。
  汇总行的「池缺失 N」表示有 N 把没扫到（多半是那把枪在物品表里根本不存在）。
  不想让某个 mod 的武器进来，在 "weaponPool".excludeMods 里填它的目录名即可。

· MLOM 加载顺序管理器
  本 mod 在 MLOM 的加载顺序表里登记的名字是「综合任务优化」。
  装了 MLOM 的话，如果它显示的版本号不是 1.4.0，顺手改一下即可，不改也不影响运行。

· 当前未激活的限时活动任务不在任务表里，不会被处理。

· removeTimeGates（移除等待期）与 sgtlaggyQuestTweaks 的同名功能在同一环境对照结果逐字段一致。


【卸载】
删掉 user\mods\QuestTuner41\ 目录并重启服务端即可。
本 mod 只在内存中改任务数据、不写数据库，卸载后任务条件立刻回到原版，不用清档。


【更新记录】
v1.4.0 武器池按「原型」认枪 —— 以前扩不动的任务现在能换枪了：
         ① 旧版只认「声明了克隆关系」的武器，模组里照原型枪改出来的变体
            （DWV 的各种改型、SOCOM 的 DDM4A1、WTT 的 Ak5C 等）不在其中，
            任务死守「必须用那一把」，玩家会以为「武器优化没生效」。
            现在按原型归组：变体只要用的是同一把原版枪的模型容器，
            就和原版那把及同族变体互相算数（两个方向都算）。
         ② 顺带补上反方向那半边：任务点名原版枪时，同族的模组变体现在也算数。
         ③ 新增开关 "weaponPool".sameModelFallback（出厂 true），填 false 即回到 1.3.0 的行为。
         ④ 实测（测试环境）：多识别 18 组，可用武器注入 614 → 782 把，
            多 4 个任务挂上「（武器已优化）」。
v1.3.0 任务名标记拆成两类 + 旧配置自动升级：
         ① 「（已优化）」拆成「（任务已优化）」（条件被改过）与「（武器已优化）」
            （武器池真的给它加过枪）两枚独立标记，同一任务可同时挂两枚；
            此前武器池是被排除在标记之外的，玩家看不出哪些任务的可用武器被扩充过。
         ② 武器池现在也会读 exemptQuests / onlyQuests：之前它绕过这两份名单，
            被你排除掉的任务照样会被加枪。既然标记已经公开，这条契约缺口必须补上。
         ③ 老配置自动升级：markerSuffix 的旧暗号 (S4A) 会被自动关闭并在日志说明，
            你自己写过的任何值一律原样保留，且不会回写你的配置文件。
v1.2.0 首次给任务名加优化标记：
         被改过条件的任务在【任务名】尾部挂「（已优化）」，在任务列表里直接可见。
         此前只有一个写在任务目标行尾部的暗号 (S4A)，而且只覆盖「击杀目标被改」一种情况，
         改角色白名单、改区域限制的玩家完全看不出来。
v1.1.1 配置容错与报错定位：
         ① 最后一项多写一个逗号不再让整份配置作废（以前会静默失效，表现为「mod 好像没生效」）；
         ② 配置写坏时日志直接给出错在第几行、并把那一行前后打印出来
           （以前给的行号从 0 数起，照它去文件里数永远差一行）。
v1.1.0 修「开『不限 AI 种类』后，杀丧尸反而任务失败」：
         完成条件被放宽成「任意目标」时，与之矛盾的失败条件现在会自动移除。
         注：带指定角色的任务（击杀掠夺者、指定 Boss 等）本来就不受「不限 AI 种类」影响，
         那是设计如此；真要「什么都算」得用 removeTarget。
         另：配置并入单个 config.json（武器池分区已并入），每个键带中英文注释。
         更早的若干代次从未对外发布，已合并进本版。
